# Rxova Journey Docs

Documentation site for `@rxova/journey-core`, `@rxova/journey-react`,
`@rxova/journey-devtools-bridge`, and the Chrome DevTools extension. Built with
[Astro Starlight](https://starlight.astro.build/), sharing chrome and design
tokens with the other rxova docs sites through
[`@rxova/brand`](https://www.npmjs.com/package/@rxova/brand).

Production docs URL: `https://rxova.org/packages/journey/`

## Run locally

From the repository root:

```bash
pnpm install --frozen-lockfile
pnpm run docs          # dev server on http://localhost:4321
```

## Build

```bash
pnpm run docs:build
```

Static output lands in `apps/docs/dist`. The build is a real gate, not just a
compile: `starlight-links-validator` fails it on any broken internal link.

### Building at the aggregator base path

The site is standalone at the domain root by default, but rxova.org mounts it
under `/packages/journey/`. Absolute references that only work at the root are
invisible in a root build and break once mounted, so CI builds it both ways:

```bash
DOCS_URL=https://rxova.org DOCS_BASE_URL=/packages/journey/ pnpm run docs:build
```

Write internal links as relative file links (`./architecture.md`) and they stay
correct under both. `src/plugins/rehype-relative-doc-links.js` resolves them to
real, base-aware URLs at build time — Astro's content layer does not do this on
its own, and a raw `./foo.md` href ships to the browser and 404s silently.

## Structure

| Path                         | What it is                                                      |
| ---------------------------- | --------------------------------------------------------------- |
| `src/content/docs/core`      | Core runtime docs                                               |
| `src/content/docs/react`     | React bindings docs                                             |
| `src/content/docs/bridge`    | Devtools bridge docs                                            |
| `src/content/docs/devtool`   | Chrome DevTools extension docs                                  |
| `src/content/docs/index.mdx` | The homepage (Starlight `splash` template)                      |
| `src/components/home`        | Homepage-only components                                        |
| `src/assets`                 | Images referenced from docs, run through Astro's image pipeline |
| `astro.config.js`            | Sidebar, base path, and the links validator                     |

The sidebar is declared explicitly in `astro.config.js` rather than
autogenerated: the Core section groups pages that share a directory and pulls
`persistence` and `autosave` into "Plugins" from outside `plugins/`, neither of
which directory-based autogeneration can express.

## Release notes in docs

Per-package release notes pages are generated from changelog files:

| Source                                  | Generated page                         |
| --------------------------------------- | -------------------------------------- |
| `packages/core/CHANGELOG.md`            | `src/content/docs/core/releases.md`    |
| `packages/react/CHANGELOG.md`           | `src/content/docs/react/releases.md`   |
| `packages/devtools-bridge/CHANGELOG.md` | `src/content/docs/bridge/releases.md`  |
| `apps/devtools/CHANGELOG.md`            | `src/content/docs/devtool/releases.md` |

```bash
pnpm run docs:release-notes:sync    # regenerate
pnpm run docs:release-notes:check   # fail if stale
```

## API docs quality gate

Public callable exports (from each package's `src/index.ts`) must carry TSDoc
summaries:

```bash
pnpm run docs:api:check
```

## Deploy

Docs are published as part of rxova.org by the `rxova/rxova-website` aggregator,
not from this repo's Pages. The aggregator never builds them — it only validates
and publishes what it is sent, so this repo owns the build end to end.

`.github/workflows/docs.yml` is the sender (gate 1 of the contract in
`rxova/rxova-website` `docs/INPUTS-CONTRACT.md`). On a push to main it:

1. builds the site with `DOCS_BASE_URL=/packages/journey/`,
2. uploads `apps/docs/dist` as the workflow artifact **`docs-dist`** — the fixed
   name the aggregator downloads by, with `index.html` at the artifact root,
3. fires a `docs` `repository_dispatch` at `rxova/rxova-website` naming this run
   (`{ schema: 1, project: journey, ref, sha, run_id, base, framework }`).

The aggregator then re-validates the metadata and the dist, persists the dist as
a release asset, and redeploys. A rejection at either gate fails that ingest run
and leaves the live site untouched — a bad push here cannot take rxova.org down,
it just does not publish.

## Migration note

This site was migrated from Docusaurus. `scripts/migrate-content.js` is the
one-shot script that did it, kept in the repo so its transforms stay auditable
next to the diff they produced. It is not part of any build.
