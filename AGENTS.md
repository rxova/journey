# Working on this repo as an agent

`@rxova/journey`: a declarative journey graph for non-linear UI flows. Three published packages
(`@rxova/journey-core`, `@rxova/journey-react`, `@rxova/journey-devtools-bridge`), the Chrome
DevTools extension, the docs site, a demo and the examples.

[`CONTRIBUTING.md`](CONTRIBUTING.md) is the reference and stays the source of truth: the
architecture, the shared setup, the gate and the release process. This file only covers what an
agent gets wrong.

## Where things live

| Path                                         | What it is                                                                                   |
| -------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `packages/*/src/`                            | The published code. `src/internal/` holds helpers that are bundled, never exported.          |
| `packages/*/scripts/build.ts`                | esbuild (minified ESM + CJS with source maps), then `tsc` for the per-file declarations.     |
| `apps/docs/src/content/docs/*/api/reference` | **Generated by TypeDoc and gitignored.** Edit the TSDoc in the source instead.               |
| `apps/docs/src/content/docs/*/releases.md`   | **Generated from the changelogs** by `pnpm run docs:release-notes:sync`. Never edit by hand. |
| `scripts/`                                   | Repo-specific scripts with their tests. Everything generic comes from `@rxova/repo-config`.  |
| `test/source-aliases.ts`                     | Points every suite at the workspace sources, so no suite needs a build first.                |

## The gate

```bash
pnpm verify     # what pre-push runs, in CI's order — run it before you claim done
```

The steps are `repoConfig.verify.steps` in the root `package.json`. Scope while iterating:
`pnpm --filter @rxova/journey-core test`.

## Invariants, and what enforces them

| Invariant                                                                  | Enforced by                                     |
| -------------------------------------------------------------------------- | ----------------------------------------------- |
| Zero runtime dependencies; `react` and `immer` are peers only.             | review + `pnpm size` budgets                    |
| 95% coverage per file in every package and the extension.                  | each package's `vitest.config.ts`               |
| Every callable public export has a TSDoc summary.                          | `rxova-repo-config check-tsdoc`                 |
| Hand-written docs never name a removed API (`repoConfig.docs.banned`).     | `rxova-repo-config check-banned`                |
| Core, React and the bridge share one major version.                        | `rxova-repo-config check-majors`                |
| One package per changeset, and none a changelog would misread as metadata. | `rxova-repo-config lint-changesets`, in CI      |
| Packages import each other by name, and only once declared.                | the `workspace/enforce-package-boundaries` rule |
| Tests reach internals only through the package's `/testing` alias.         | `no-restricted-imports` on `__tests__`          |

## Traps

- **`src/internal/` is not `@rxova/ts-utils`.** The development warnings there treat
  `NODE_ENV=test` as quiet and read the environment through `globalThis`; the devtools bridge's
  enable check is conservative in a way a bundler-rewritten `process.env.NODE_ENV` would change.
  Swapping them for the ts-utils versions changes behaviour.
- **A build ships no `dist/internal/`.** The helpers are bundled into the JS and appear in no
  public type, so the build removes their declarations.
- **The pre-push hook runs the full `pnpm verify`** (minutes, the docs build included).
